## The answer

### 🛠️ The Utility: src/utils/services/update-task-in-array.js

Here is how you can implement this.
We will use the Spread Operator (...) to make the merging automatic.

```js
/**
 * Generic Utility to update an object within an array
 * @param {Array} tasksArr - The current list of tasks
 * @param {Object} updateData - Object containing the ID and the fields to change
 * @returns {Object|null} - The updated task or null
 */
export const updateTaskInArray = (tasksArr, updateData) => {
  const { id } = updateData;
  const index = tasksArr.findIndex((task) => task.id === id);

  if (index < 0) return null;

  // Merge existing task with new data
  // This overwrites existing properties with whatever is in updateData
  tasksArr[index] = {
    ...tasksArr[index],
    ...updateData,
  };

  return tasksArr[index];
};
```

### 🚀 How to use it in your Services

1. Updating Description

```js
// Inside service-update-task.js
const updatedTask = updateTaskInArray(tasks, {
  id,
  description: newDescription,
  updatedAt: new Date().toISOString(),
});
```

1. Updating Status (Future proof!)

```js
// Inside service-update-status.js
const updatedTask = updateTaskInArray(tasks, {
  id,
  status: "done",
  updatedAt: new Date().toISOString(),
});
```

### 🔍 Why this is a "Senior" Design

1. Flexibility:
   You don't have to name every property inside the utility.
   If you decide to add a priority field later,
   this utility already knows how to handle it!

2. Predictability:
   It always returns either the full task object or null.
   Your Controller will love this consistency.

3. Purity:
   Notice the utility doesn't know about tasks.json.
   It only cares about the Array you gave it.
   This makes it extremely easy to test.
